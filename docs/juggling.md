# 颠球

输入一段颠球视频，数出每一次触球、连击、每一颠的高度，渲染成带特效的竖版成片。

```bash
python -m combocam run in.mp4 -o out/demo
```

## 怎么做的

### 1. 找球

- **整帧检测**：每帧缩到 640×640 给 YOLOX-s，只留 `person` 和 `sports ball` 两类。
- **人周围放大复检**（`combocam/analyze.py` 的 `ZOOM`）：竖版画布缩小 3 倍后球常常只剩 10–20 像素，暗处、逆光剪影里检测分只有 0.1 上下。
  所以每帧在主要人物周围裁一块正方形（边长约 1.3 倍人高，下边在脚下一点），单独再检一次球，和整帧的结果合并。
  - 整帧检测在这块区域里已经有分数 ≥ 0.5 的球，就跳过，省时间；
  - 放大后检出的、半径不到 0.25 × 0.065 × 人高的小东西（远处的小球、反光）不要；
  - `COMBOCAM_ZOOM=0` 关掉。
- **漏检处局部复检**（`--refine online`）：轨迹断了的地方，在预测的位置裁原图再检一次。

### 2. 选出"被颠的那个球"

`combocam/track.py`：把所有帧的候选框连成一张有向无环图，求得分最高的一条路径（前后帧一起看）。

- 节点得分 = 2 × 置信度 − 0.25：高分检测是骨架，低分候选只有在能把前后高分点连起来时才会被选上；
- 尺寸和球径偏差过大的扣分；**静止不动的候选**（场边另一个球、地上的球、白鞋）不给分；
- 边代价 = 速度平方 + 跳帧罚分，超过物理速度上限、尺寸突变的不连；允许丢失一段后重新捕获。

### 3. 触球

`combocam/events.py`：两次触球之间球只受重力，y(t) 是抛物线、x(t) 近似直线。

- 逐段拟合抛物线，**相邻两段的交点就是触球时刻**（亚帧精度）；拟合曲线也用来补被身体挡住的帧；
- 判据有两个，取并集：纵向位置的 V 形低点，和速度突然由下转上的"冲量"。

### 4. 哪些不算触球

人体关键点（RTMPose-m Halpe26，带脚趾、脚跟）在第 1 遍检测时对主要人物顺带推理。判断都按 `combocam/events.py` 的 `P`：

- **地面线** = 支撑脚的脚底，比人框底边准，近景、仰拍、横屏截断都不受影响；
- **落地**：球底低于地面线，并且是从地上挑起或被动反弹（弹起不到落下的 75%）。
  反过来，落下至少一个球半径、弹起不低于落下的 85%、球底没有明显低于地面线的，算贴地的脚触球（被动落地只能弹回 25%–70%）；
- **球没碰到人**：看得见脚，而脚、大腿、头、胸离球都在 2.5 个球半径以外，并且是被动反弹，判成落地（球在镜头前落地、射门撞网、地上滚的球磕一下）；
- **从地上挑起**：触点前球几乎没在下落（不到半个球半径），球底离地面不到 1 个球半径，不算触球。球停在脚背上再挑起，离地面高，照样算；
- **地上玩球**：触点前后 0.5 秒里球有 40% 以上的时间贴着地面（真触球最多 35%）；
- **手接、手托、球在手臂上滚**：球贴着前臂、脚和膝都不在附近，不计数并断开连击，成片上提示"用手 · 重新计数"；
- **头上平衡、颈后停球**：触点在头胸附近，之后 0.4 秒里球相对颈肩几乎不动（< 0.75 个球半径；颠起来的球 ≥ 0.9，多数 ≥ 1.7），
  或者球一直贴着头、手在旁边扶着：不计数，也不断连击；
- **离人 2 米以外的弹跳**不算；**前后 6 帧内都没检测到人**时不算（人走出画面、球自己在弹）；
- **触球部位**按最近的关键点判断（脚、大腿、头、胸）。

另外两处：横屏素材放进竖版画布后，人框底边被真实画面的下边缘截断，地面线按真实画面算；
慢动作素材的"间隔过长断连击"按重力反推的慢放倍数放宽。

### 5. 高度和比例尺

用 5 号球直径 22 cm 做比例尺；同时从抛物线拟合出的重力加速度反推一个比例尺做交叉校验，差得多时（比如慢动作视频）给出提示。
球的大小只用人附近的帧来估，远处滚走的球看起来小，会把基准拉低。

## 准确率

所有测试视频都来自 Pexels（清单见 `samples/manifest.json`），触球真值是人工逐帧看缩略图标的，±4 帧算对上。
"召回" = 真触球里数到的比例；"精确率" = 数出来的触球里真的比例。评估方法和命令见 [evaluation.md](evaluation.md)，
每一步改动解决了什么、试过哪些方案、对准确率的影响见 [开发记录](development.md#3-颠球)。

### 留出测试集

做法：另找素材，**先逐帧标注（标的时候不看算法结果），再第一次跑**。第一次跑的结果是那时规则的独立准确率；
之后看过错误、改过规则，这批就不再算留出集。

| 测试集 | 第一次跑（独立） | 现在 |
|---|---|---|
| 第 1 批 12 段（`samples/heldout/`，145 次） | 74.8% / 93.9%（只看轨迹和人框） | 98.6% / 99.3% |
| 第 2 批 11 段（`heldout2/`，117 次，含 4 段没颠球） | 94.9% / 94.1%（加了关键点） | 95.7% / 98.2% |
| 第 3 批 15 段（`heldout3/`，66 次，含 6 段没颠球） | 97.0% / 73.6% | 97.0% / 91.4% |
| 第 4 批 19 段（`heldout4/`，79 次，含 8 段没颠球） | 93.6% / 83.9% | 92.4% / 93.6% |
| 第 5 批 18 段（`heldout5/`，60 次，含 12 段没颠球） | **86.7% / 86.7%** | 91.7% / 88.7% |

- 第 5 批是前四批都调完以后才下载、才标的，86.7% / 86.7% 是规则定型后的独立结果。它比前四批难：日落剪影、雪地只拍到腰以下、
  多镜头剪辑、手上动作多。之后为它加了"人周围放大复检"，所以"现在"那一列的 91.7% 偏乐观。
- 手机固定、全身入镜、光线正常的视频，准确率应该在两者之间，要用户实拍的视频才能定。
- 另有 4 段（53 次触球）最早逐帧核对过的视频（`samples/labels.json`），现在全部数对，0 误报；但最初的规则就是在它们上面调的。

### 放大复检的效果

| | 不放大 | 放大复检 |
|---|---|---|
| 第 5 批（60 次） | 86.7% / 89.7% | **91.7% / 88.7%** |
| 第 1–4 批（407 次） | 96.1% / 97.0% | 96.3% / 96.6% |

- 第 5 批日落剪影那段漏的 3 次全找回来了：按真触球前后有没有检出球算，没检出的从 3 次降到 0 次；
- 第 1–4 批基本不变（规则是照着旧检测调的，换检测后多了一两次误报）。

当时在第 4 批上比过三种方案，最后选了"不确定才放大"：

| 方案 | 召回 / 精确率 | 每帧耗时（GTX 1050 Ti） |
|---|---|---|
| 原来 | 92.4% / 93.6% | 85 ms |
| 每帧都放大 | 93.7% / 92.5% | 128 ms |
| 换更大的 YOLOX-m | 89.9% / 92.2% | 177 ms |
| 不确定才放大（采用） | 92.4% / 93.6% | 96 ms |

### 还错的地方

- **漏数**：
  - 球从画面上方掉进来、刚进画面就被颠，漏检的一段太长，接不上轨迹；
  - 逆光过曝时手边的一下被当成手接；镜头剪辑很碎时会漏；
  - 画面里有好几个球、其中一个在后面地上慢慢滚时，选轨迹偶尔跟到那个球上（选轨迹不看离人远近）；
  - 脚被挡住或关键点缺了脚时，低位触球可能当成落地。
- **多数**：
  - 在地上用脚踢、拨球，球弹得比较高时偶尔算成触球（马路上两人带球）；
  - 手里拿着、手抛的球离前臂的距离刚好在门槛上下时；排球用手托球；
  - 球停在脚背上绕脚，有时算成两次，或记在落到脚上那一刻而不是挑起那一刻。
- **分不清**：碰地后马上被脚铲起，和贴地的脚触球，只靠轨迹和关键点分不清，目前按脚触球算（宁可少断一次连击）。
- **触球部位**只在近处准；成片里没有显示部位。

## 调规则

改了计数逻辑后，不用重跑检测：

```bash
python tools/eval/reanalyze.py out/<名>.track.json          # 用缓存的检测结果重算轨迹 JSON
python tools/eval/eval_heldout.py --set heldout5 -v         # 留出集：逐条列出误报、漏检
python -m pytest tests/test_events.py                       # 合成数据上的回归测试
```
