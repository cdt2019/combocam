# 速度

## 实测

**本机**（GTX 1050 Ti 4 GB + i7-8750H 6 核），29 秒的颠球测试视频（877 帧）：

| 环节 | 用时 |
|---|---|
| 分析（检测、放大复检、局部复检、关键点、计数） | 62 s（GPU）；只用 CPU 时 YOLOX-s 每帧约 0.76 s，要 11 分钟以上 |
| 渲染 + x264 编码（含 3 秒片尾） | 24–25 s |
| 渲染 + NVENC 编码 | 17.3 s |
| 只渲染不编码 | 16.0 s |

**云端**（V100 16 GB + 8 vCPU），同一段视频（在加"人周围放大复检"之前测的，放大复检让分析多 5%–13%）：

| 项目 | 用时 |
|---|---|
| 分析 | 15.6 s |
| 渲染 + x264 编码 | 19.1 s（不编码 12.2 s） |
| 单条端到端 | 35.0 s |
| 3 条同时跑，平均每条 | 30.4 s（每小时约 118 条；CPU 已满，4 条同时跑不会更快） |

GPU 平均只用了 17%–24%，**瓶颈在 CPU**：每条视频约 240 核·秒，大头是 x264 编码（约 60）、分析（约 70，含解码和推理前后处理）、
画特效（约 50）、解码（约 15）。开 GPU 编码（NVENC）能省下 x264 那部分。

跳绳只跑人体检测和关键点，16 秒的 4K 视频全流程约 21 s（同一台 V100），大头是 4K 解码和缩放。

## 提速做了什么

下面这些都不改变结果：轨迹 JSON 逐项相同，成片逐帧像素 MD5 相同。

- **分析三级流水线**（`combocam/analyze.py` 的 `_pass1`）：解码 + 亮度统计 + 检测预处理、检测推理 + 在线复检、关键点各占一个线程，
  GPU 推理时 CPU 不再空等。
- **预处理挪到 GPU**（`combocam/onnx_io.py`，启动时在内存里改模型图，模型文件不动）：
  - 检测模型直接吃 uint8 图，转 float、换维度在图里做，拷到显卡的数据 4.9 → 1.2 MB；
  - 图里先挑出人或球分数够高的候选行，只拷回这些行（原来拷回整张 8400×85）；
  - 关键点模型的 BGR→RGB、归一化也在图里做。

  检测每帧 13.0 → 9.2 ms，关键点 7.5 → 6.1 ms。`python tools/debug/check_onnx_io.py in.mp4` 逐帧核对模型原始输出、最终的框和关键点逐位相同。
  需要 `onnx` 包，只在用 CUDA 时启用，`COMBOCAM_GPU_IO=0` 关掉。
- **渲染线程自己转 YUV**（`render/pixels.mjs`）：FFmpeg 的 RGBA→YUV 转换在编码进程里单线程跑，CPU 满载时成了整条流水线的上限；
  改成各渲染线程自己转，管道里每帧也从 8.3 MB 降到 3.1 MB。和无损帧比，画质不变（RGB PSNR 36.0 vs 35.9 dB）。
- **C 原生模块**（`render/native/pixels.c`，可选）：RGBA→YUV 和保护层渐变压暗（启动时用 Skia 画一遍渐变得到每行查找表，
  拷视频帧时顺手查表），每帧省约 20 ms。
- **少分配、少拷贝**：不再每帧新建 `ImageData`，视频帧直接写进画布内存，帧缓冲循环使用。
- **只解码一次**（Linux）：分析解码时用 FFmpeg `tee` 把按画布帧率取好的原始帧另存一份到内存盘 `/dev/shm`，渲染直接读它，
  省掉第二次 H.264 解码（单条约 −2 s，3 条并发每条少约 8 核·秒）。
  - 只缓存 8 bit 4:2:0 视频；超过 `COMBOCAM_FRAME_CACHE_GB`（默认 6）或内存盘剩余不足 2 GB 时不缓存；`--no-frame-cache` 关闭；
  - 写缓存失败不影响分析，写完核对大小，不完整就让渲染自己解码；跑完一定删掉；
  - 超过 250 万像素的源（4K）不缓存原尺寸帧：一帧 12 MB，读回来再缩放比直接解码还慢。跳绳改存缩放到画布之后的 yuv420p 帧，4K 源也划算。
- **NVENC 参数**按 VMAF 调过（`-preset p5 -cq 27 -rc-lookahead 20 -bf 3`）：30 秒样片 28.8 MB、VMAF 96.5；
  libx264 `veryfast` `crf 20` 是 31.4 MB、95.7。

## 为什么不边分析边渲染

试过只用前一部分视频的检测结果先算计数、先渲染。42 段测试视频里，落后 3 秒的检查点只有 55% 和整段算出来的完全一致，有的连第几次触球都不同。
原因是选球轨迹（全片最优路径）、球的大小、重力比例尺都是整段一起算的。为了不改变计数，选了上面这些不影响结果的提速。

## 还能做的

- 解码也交给 GPU（NVDEC）：每条视频解码一次要 12–17 核·秒，能全省下。输出是 nv12、颜色转换的代码路径不同，要逐帧核对分析输入和成片；
- 换 TensorRT FP16：检测结果会有细微变化，要重跑留出集评估。
