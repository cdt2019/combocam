# 跳绳

只看人体关键点（绳子太细太快，30 帧的视频里每圈只在一两帧里有一道淡弧线），复用颠球的人体检测和 RTMPose。

```bash
python -m combocam jumprope in.mp4 -o out/jr                 # 单人
python -m combocam jumprope in.mp4 -o out/jr --mode pk        # 双人 PK
```

## 计数

`combocam/jumprope.py`，阈值在 `P` 里：

- **一跳 = 髋部高度的一个波峰**，并且两只脚都离地（较低那只至少是较高那只的 22%）；单脚抬起是交替抬脚时的换脚，不算。
- **垫步和小动作**：起伏比前后相邻候选小很多（不到一半）的，按节拍分：
  - 离相邻候选只有半拍左右的，是两跳之间的垫步，不算；
  - 前后两拍多内有一边没有大的跳的，是起跳前、停下后的小动作，不算；
  - 两边隔一拍左右都有大的跳的，是跳得低的真跳，算。
- **节奏**按这段视频自己估的周期缩放，慢动作也能数；间隔超过最近节奏的 1.8 倍算**断绳**。断绳不清零总数（和一分钟跳绳测试一样按总数计）。
- **脚被画面底边切掉**时只看髋部，并给出提示。

### 慢动作

腾空时身体自由落体，髋部轨迹是加速度为 g 的抛物线。按假定身高 1.65 m 把像素换成米，量出"视在重力"，慢放 k 倍时它是 9.8 / k²。
正常速度的视频在 8–11 m/s²（儿童偏大），2 倍慢放约 2.5，4 倍约 0.6。低于 6.5 就当慢动作，跳速、用时按 √(9.8 / g) 换回真实时间（大约数）。

### 摇绳节奏核对

绳子每过脚一次，手腕转一圈。`summary.arm_sync` 是最长那组里手腕（相对肩膀）的上下位置在"一跳的间隔"上的自相关：
数对了接近 1，一圈数成两跳（或反过来）是负的。能看清手的视频在 0.5–0.9；逆光剪影、多人、镜头来回摇的接近 0，报告里给提示。
它只能发现"节奏对不上"，查不出组头组尾多数或少数一两跳。

### 跑步跳和一圈跳两下

- **跑步跳**（每步都过绳、左右脚交替发力）：一步髋部起伏大、一步小，小的那步单脚着地，会被"两只脚都离地""比相邻小很多"去掉，只数到一半。
  手腕节奏清楚（自相关 ≥ 0.5）、髋部每圈都起伏一次、却只数到一半时，改成"一只脚离地就算"再数一遍，节奏对上摇绳节奏才用。
- **一圈跳两下**（`bounce`，初学者、小孩常见：绳子在头顶时原地垫一下，过脚时再跳一下，两下一样高）：
  数出来的间隔只有摇绳周期的 0.4–0.62 倍时，只留"过绳"的那一下。依据是标注过的 33 段视频里，人跳到最高的那一刻都落在摇绳周期的 0.5–0.6 处
  （0 = 手腕相对肩膀最高）；两簇跳里留离 0.55 近的那簇。`summary.bounce = "double"`。

### 被挡住、看不清

- **漏掉的一跳**：相邻两跳隔了约两拍、中间有个被去掉的候选离两边都约一拍（脚点被挡、起伏小了点），补回来，不当成断绳；
- **人短暂不在画面里**（有人从镜头前走过）：空档不算断绳；空档 ≤ 2 秒、空档后的跳正好落在节拍上时，按节拍补上看不见的跳（`inferred`，成片照样计数、不画脚下效果）；
- **髋部关键点出错**：某一帧肩膀和头彼此一致、都和髋部差出 1.2% 身高且方向相同，就把髋部换成肩膀和头的平均（只换不超过 0.2 秒的一段）。
  直接取三处的中位数在压力测试里更好，但真实视频里低头看绳、走近镜头时头和肩膀自己在动，会多数，所以没用。

遮挡压力测试（`tools/eval/jumprope_occlusion.py`）：在标注视频的关键点上随机放 0.4–1.2 秒的遮挡块（合计约 30% 时间），15 个随机种子：

| 遮挡 | 召回 / 精确率 |
|---|---|
| 脚和脚踝丢了 | 99.5% / 96.5% |
| 膝盖以下丢了 | 99.5% / 96.5% |
| 整个人没检测到（看得见的跳） | 77.4%（93.5%）/ 95.2% |
| 髋部、肩膀或头乱跳（±2% 身高） | 100% / 100% |

### 多人入镜

`combocam/people.py`：关键点那遍给画面里每个人都跑（远处的小人、第 6 个以后的不要），再记一份衣服颜色（躯干的色调-饱和度直方图）。

- **连轨迹**：相邻帧按人框重叠度配对，衣服颜色对得上的优先；颜色对不上但人框几乎没动的照样接上；人框也明显变了、连续 3 帧都对不上才拆开；
- **合并**：镜头摇走又摇回来、被别人挡住时断成几段，时间上不重叠、衣服颜色像、大小差不多的接回一条；
- **选人**：每条轨迹单独计数，跳数够格（≥ 3 且 ≥ 最多那条的 40%）的算"在跳绳"，其中挑离镜头近、在画面里时间长的。

## 双摇

`rope_passes`：数每一跳"离地到下一跳离地"之间手腕（相对肩膀）到最高点几次：1 单摇、2 双摇、3 三摇。手腕关键点会抖，所以还要：

- 真实腾空 ≥ 0.27 秒（三摇 ≥ 0.42 秒）；
- 每一圈手腕抬起 ≥ 2% 身高（真双摇 2.3% 以上，关键点抖出来的 0.1%–1.4%）；
- 脚离地 ≤ 30% 身高（跳大绳时收腿高跳，手不摇绳、随跳甩动）；
- 整段有摇绳的节奏（自相关 ≥ 0.3）；脚不在画面里时一律按单摇。

`summary` 里有 `doubles`、`triples`、`passes`、`style`（`double` / `mixed` / `single`）。双摇为主时成片的大数字数双摇。

## 双人 PK

`--mode pk`（`--mode auto` 在两人明显一起跳时自动出 PK）：挑排名前两个在跳的人，按画面左右分成红方、蓝方，各自计数。

- 慢放倍数两人共用一个，同一段视频两人的跳速才能比；
- 领先要领先 2 个才算：两人差不多同时跳时，谁先落地谁就"领先 1 个"，每跳都在换；
- `--pk-rule`：`auto`（两人都以双摇为主时比双摇个数，否则比总跳数）、`jumps`、`doubles`、`passes`（绳子过脚次数，双摇算 2）；
- `auto` 判"一起跳"：两人都在跳、同时在画面里的时间占短的那人一半以上、跳数和个子都差不到一倍。

## 准确率

人工按"绳子过脚一次算一跳"逐跳标注，±4 帧（或一跳周期的 20%，取大的）算对上。每一步改动对准确率的影响见 [开发记录](development.md#4-跳绳)。

| | 段数 | 跳数 | 召回 | 精确率 | 计数完全对 |
|---|---|---|---|---|---|
| 第 1 批（4 段调规则 + 2 段规则定好后才标） | 6 | 73 | 100% | 100% | 6 / 6 |
| 第 2 批（规则调完后才标，验证集） | 28 | 484 | 99.6% | 98.4% | 26 / 28 |

- 第 2 批的标注不看算法的逐跳结果，只用像素"运动轨迹图"（`tools/label/jumprope_kymo.py`：人的中线竖带按时间排开，每跳一个拱形）。
  40 段里 12 段没法逐跳标（只拍到腿、剪辑来回切、交替高抬腿看不出哪一步过绳……原因写在标注的 `exclude` 里）。
- 第 2 批不对的两段：8925437 一圈跳两下，数成 15（应为 8），后来做了"一圈跳两下"后数对，但这段就不再是独立验证了；6389572 第一跳在视频第 9 帧，没数到。
- 双摇：标了 10 个，判对 10 个、没有误判；但这两段是做双摇时看过的。三批 114 段里判成双摇的只有 4 段，都逐跳核对过。
- 素材以健身房、远景、慢动作为主，单人、全身、光线好，没有手机竖拍的日常视频，数字要打折看。

## 绳子能不能识别

`tools/debug/jumprope_rope.py`：在脚附近取一条横带，和前后几帧的中位数相减，数"像细线一样在动"的列。

- 粗的彩色绳、转得慢、固定机位：信号的波峰和人工标的过绳时刻基本对上；
- 普通细绳、正常速度、手持拍：信号淹没在镜头晃动和地面纹理里。

所以计数靠人体关键点，绳子只能当辅助（摇绳节奏核对是从手腕间接看绳子）。要可靠识别绳子得专门训练模型，最好再用 60 帧拍。

## 已知局限

- 交替抬脚跳：每圈绳子人可能起伏一次也可能两次，现在按"两只脚都离地才算"处理，换一种步法未必对；
- 空跳（不拿绳）、绊绳：只看人体动作看不出来，要看绳子或听声音；
- 视频一开始就在跳时，第一跳可能数不到；剪辑拼起来的视频按其中一段算；
- 双人 PK 只在两段素材上看过，真实的"反超"只有单元测试覆盖；两个人互相遮挡的情况没测过。
